# Customer Insights Dashboard data dictionary

Dataset version **1.0**, generated **17 November 2026**. This document defines the supplied PostgreSQL records used by the Full Stack Developer Technical Assessment. The complete schema is in `sql/01_schema.sql`.

## Conventions

| Item | Definition |
| --- | --- |
| Database schema | `public`; unquoted lowercase table and column names. |
| Tables | `customers`, `staff`, `deals`. There are no additional application tables. |
| IDs | Positive `integer` primary keys with `GENERATED BY DEFAULT AS IDENTITY`. Seed IDs are stable. |
| Currency | GBP for every deal. No conversion or per-row currency field is required. |
| Amount unit | Pounds, not pence: `1234.56` means £1,234.56. |
| Money representation | `numeric(12,2)`; non-negative finite values from `0.00` through `9999999999.99`. Zero is valid. |
| Timestamps | `timestamp with time zone` (`timestamptz`), with explicit UTC literals in the seed. Display dates consistently in UTC. |
| Text | UTF-8. Names and companies can contain spaces, apostrophes and accented characters. |
| Missing values | SQL `NULL`, not an empty string, a zero ID or the text `"null"`. |
| Case | Status and category values are canonical and case-sensitive. Customer searching is case-insensitive. |

Monetary arithmetic must preserve decimal precision. Drivers may return PostgreSQL `numeric` values as strings; parse and calculate deliberately. Keep precision through calculation and round at display time. Display averages using rounding to the nearest penny with half-penny ties rounded up (`ROUND_HALF_UP`) for non-negative values.

`timestamptz` values represent instants; the original input timezone name is not retained. A database session may render the same instant in its configured timezone, so choose UTC when serialising and displaying it. The supplied Compose service sets its database timezone to UTC.

## Customers

One row represents one customer. Names and companies are not unique; identify a customer by `id`.

| Column | PostgreSQL type | Nullable | Default | Meaning and constraints |
| --- | --- | --- | --- | --- |
| `id` | `integer` | No | Identity sequence | Primary key; greater than zero. |
| `full_name` | `text` | No | None | Customer's full display name. Must not be blank after trimming. |
| `email` | `text` | No | None | Customer email. Must not be blank; a unique index on `lower(email)` prevents duplicates differing only in case. The schema does not perform full email-address syntax validation. |
| `company` | `text` | Yes | `NULL` | Associated company. `NULL` means none recorded. A present value must not be blank. Multiple customers may share the same company. |
| `created_at` | `timestamp with time zone` | No | `CURRENT_TIMESTAMP` | Creation instant of the customer record. It is not the time of the first deal. Seed values are fixed. |

Customers may have zero, one or many deals. Preserve customers with no completed deals in the unfiltered table and in the average-spend denominator.

## Staff

One row represents one staff member. These are staff profiles, not application user accounts.

| Column | PostgreSQL type | Nullable | Default | Meaning and constraints |
| --- | --- | --- | --- | --- |
| `id` | `integer` | No | Identity sequence | Primary key; greater than zero. |
| `full_name` | `text` | No | None | Staff display name; must not be blank. |
| `email` | `text` | No | None | Staff email; must not be blank. A unique index on `lower(email)` enforces case-insensitive uniqueness within `staff`. |
| `role` | `text` | No | None | Descriptive job role; must not be blank. No role enum or authorisation rules are implied. |
| `created_at` | `timestamp with time zone` | No | `CURRENT_TIMESTAMP` | Creation instant of the staff record. Seed values are fixed. |

The snapshot uses `Concierge Manager`, `Concierge Specialist`, `Relationship Manager` and `Operations`. These labels are data values, not a closed database constraint. A staff member may be linked to many deals and to deals for different customers.

## Deals

One row represents one deal. A deal belongs to exactly one customer and can have at most one recorded staff member. A customer may therefore have several associated staff members across their deals.

| Column | PostgreSQL type | Nullable | Default | Meaning and constraints |
| --- | --- | --- | --- | --- |
| `id` | `integer` | No | Identity sequence | Primary key; greater than zero. Also resolves equal creation timestamps when identifying a customer's last completed deal. |
| `customer_id` | `integer` | No | None | Foreign key to `customers.id`. The referenced customer must exist. |
| `staff_id` | `integer` | Yes | `NULL` | Foreign key to `staff.id`. `NULL` means no staff member is recorded on this deal. It does not exclude a completed deal from spend or deal counts. |
| `product_category` | `text COLLATE "C"` | No | None | One of the six exact category labels below. Explicit `C` collation gives deterministic category ordering. |
| `deal_value` | `numeric(12,2)` | No | None | Total deal value in GBP pounds. No tax, fee, refund or currency adjustment is needed. The range constraint rejects negative values and `NaN`. |
| `status` | `text` | No | None | One of `pending`, `completed` or `cancelled`, exactly as written. |
| `created_at` | `timestamp with time zone` | No | `CURRENT_TIMESTAMP` | Creation instant of this deal. It is not a completion timestamp or status-change timestamp. |

Both foreign keys use `ON DELETE RESTRICT` and `ON UPDATE RESTRICT`. A referenced customer or staff record cannot be deleted or have its ID changed while a deal points to it. `NULL` staff links remain valid. No cascading deletion is configured.

The seed places deal creation after customer creation, but this cross-table chronological rule is not a database constraint. There is no `completed_at`, status history, ownership field, permission mapping, soft-delete field or separate product table.

## Allowed deal statuses

| Value | Meaning | Included in purchase metrics |
| --- | --- | --- |
| `pending` | Deal has not been completed. | No |
| `completed` | Completed transaction for this assessment. | Yes, including a value of `0.00` |
| `cancelled` | Deal was cancelled. | No |

Status is the row's current state. Do not infer completion from the amount, the date, a staff link or any other field.

## Allowed product categories

| Exact value | Example meaning |
| --- | --- |
| `Dining` | Restaurant bookings and dining arrangements. |
| `Events` | Event tickets and access. |
| `Experiences` | Activities and bespoke experiences. |
| `Luxury Goods` | Sourcing and purchasing goods. |
| `Travel` | Travel arrangements and related bookings. |
| `Wellness` | Wellness services and bookings. |

Keep these labels intact. All are non-null and in title case. Their alphabetical order is the order shown above. No extra category table or category-ID mapping is required.

## Table metric definitions

These definitions apply after selecting matching customers. Each selected customer's metrics use their **full completed deal history**, across all categories and staff members.

| Display field | Definition |
| --- | --- |
| Customer | `customers.full_name`. |
| Company | `customers.company`; use a clear placeholder when `NULL`. |
| Email | `customers.email`. |
| Total spend | Sum of `deal_value` where this customer's `status` is exactly `completed`. Use zero when there are no completed deals. |
| Total deals | Number of this customer's completed rows, including zero-value and unassigned completed deals. Use zero when there are none. |
| Favourite category | Category with the highest completed-deal **count**, regardless of spend. Break equal counts by category label ascending using the supplied `C` collation. Use a clear empty value when there are no completed deals. |
| Associated staff | Distinct non-null `staff_id` values on this customer's completed deals, resolved to staff records for display. Exclude staff linked only to incomplete deals. An all-unassigned completed history has an empty staff list. |
| Last deal | Completed row with greatest `created_at`; for equal instants choose the greatest deal `id`. Show that row's creation date in UTC. There is no completion-date column. Use an empty value when no completed rows exist. |

Do not treat `staff_id` as an account-owner assignment. Distinct staff IDs, rather than names, identify distinct staff members. The visual display order of associated staff is up to you.

For sorting, use a deterministic customer-ID tie-breaker. Missing last-deal dates appear last in either direction. Customers with the same name must remain separate rows.

## Search and filter scope

Search matches customer `full_name`, `email` or `company` using case-insensitive partial matching. A null company is simply absent; it does not stop a name or email match.

The category and staff controls each select one value, or All. Apply these rules:

1. With neither deal filter active, retain all customers who match the search, including those with no deals or only incomplete deals.
2. A selected category requires at least one completed deal in that category.
3. A selected staff member requires at least one completed deal linked to that staff ID. A null staff link cannot qualify for a specific staff member.
4. With both filters active, **the same completed deal must match both**. Separate qualifying deals are insufficient.
5. Combine the deal-filter condition and the customer-search condition with AND.
6. After selecting customers, retain their full completed history for row metrics and dashboard figures. Pagination affects which rows are visible, not the dashboard population.

## Dashboard metric definitions

| Statistic | Definition over all matching customers |
| --- | --- |
| Total customers | Count of matching customer records, before pagination. |
| Completed deal value | Sum of all completed deal values for those customers, across their full history. |
| Completed deals | Count of all completed deal rows for those customers. |
| Average customer spend | Completed deal value divided by total matching customers, including customers with zero spend or no completed deals. Round only for display. |
| Most popular category | Category with the highest completed-deal count across those customers. Resolve ties alphabetically using the supplied category collation. |

When no customers match, all numeric statistics are zero. When no completed deals exist for the matching customers, the most popular category is empty. If the count is zero, handle the denominator without dividing by zero.

## Dataset coverage

The supplied records include customers with no deals, customers with only incomplete deals, zero-value completed deals, null company and staff values, multiple staff associations, category-count ties, identical deal creation timestamps, duplicate customer names and fractional amounts. Text values include accented characters and apostrophes.

Apply the published rules consistently across these cases. The snapshot version, raw table counts and date range are recorded in `data/metadata.json`.

## Baseline indexes and permitted additions

The schema provides a primary-key index on each table and unique expression indexes on `lower(email)` for customers and staff. No extra query indexes or precomputed metric views are supplied. Candidates may add suitable supporting indexes or objects through documented migrations while preserving the supplied records and relationships.
